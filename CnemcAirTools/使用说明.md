# CnemcAirTools 使用说明

中国环境监测总站（CNEMC）空气质量数据获取工具箱，改造自开源项目 [Urbankernel/cnemc-air](https://github.com/Urbankernel/cnemc-air)。

给定一个或多个城市，抓取**城市级**（实时 / 近 24 小时 / 近 14 天日报）与**点位级**（实时 / 逐点位近 24 小时）的空气质量数据，输出**矢量点要素类（.shp）**与可选 **CSV / JSON**，坐标统一 **WGS-84（EPSG:4326）**。

数据源：`https://air.cnemc.cn:18007`（页面隐藏 JSON 接口，**无需 AK、无配额限制**）。

## 一、简介

工具箱含 **2 个工具**：

| 工具 | 作用 |
|---|---|
| 获取空气质量数据 | 按城市抓取城市级 + 点位级空气质量，输出点要素类 + CSV/JSON |
| 城市列表查询 | 拉取全国城市列表（编码/名称/经纬度/AQI），确认城市名或编码 |

本工具箱为 ArcGIS Pro 的 Python Toolbox（`.pyt`）。

## 二、环境要求

- ArcGIS Pro（arcpy 3.5.2）；
- **无需 pip 安装第三方依赖**（仅用 arcpy 自带的 requests/numpy）。

## 三、目录结构

```
github_arcgis_tools/
├── geo_common/               # 共享库（coords 坐标转换 / exporter 写要素类）
└── CnemcAirTools/
    ├── CnemcAirTools.pyt      # 工具箱入口（2 个工具）
    ├── cnemc_air_core/        # 核心包（client/retry/normalize/fetch/export/store/pipeline）
    └── 使用说明.md
```

## 四、在 ArcGIS Pro 中加载

用下面任一方式加载（推荐方式二）：

**方式一 · 添加文件夹连接**：在 ArcGIS Pro「目录」窗格中「添加文件夹连接」，定位到 `CnemcAirTools` 目录，双击 `CnemcAirTools.pyt` 打开。

**方式二 · 添加工具箱（推荐）**：打开 ArcGIS Pro →「目录」窗格 →「工具箱」→ 右键「添加工具箱」，选择 `CnemcAirTools/CnemcAirTools.pyt`。

工具箱下出现两个工具：「获取空气质量数据」和「城市列表查询」。

> 首次运行前，请确认项目根目录路径与 `.pyt` 内 `execute()` 的 `_roots` 兜底路径一致（默认已按 `F:\城市研究领域Agent\github_arcgis_tools` 配置）。

## 五、参数说明

### 5.1 工具 1：获取空气质量数据

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 城市名 | 文本 | 否* | 逗号分隔，如 `北京市,上海市` |
| 城市编码 | 文本 | 否* | 逗号分隔，如 `110000,310000`（编码优先） |
| 城市清单文件 | 文件 | 否 | 可选 `.txt`，每行一个城市名或编码（纯数字视为编码） |
| 抓取城市级 | 布尔 | 否 | 实时 + 近 24 小时 + 近 14 天日报，默认开 |
| 抓取点位级实时 | 布尔 | 否 | 默认开 |
| 抓取点位近 24 小时 | 布尔 | 否 | 逐点位 1 请求 + 1s 间隔，点位数多时耗时较长，默认关 |
| QPS | 数值 | 否 | 每秒请求数上限，默认 1.0（请勿调过高） |
| 输出目录 | 文件夹 | 是 | 成果写这里 |
| 输出 CSV | 布尔 | 否 | 默认开 |
| 输出 JSON | 布尔 | 否 | 默认开 |

\* 城市名、城市编码、城市清单文件三者至少填一项。

### 5.2 工具 2：城市列表查询

拉取全国城市列表（编码 / 名称 / 经纬度 / AQI），用于确认城市名或编码。可选按城市名筛选、导出 CSV。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 城市名筛选 | 文本 | 否 | 逗号分隔多个城市名，如 `上海,苏州`，任一命中即保留；留空则列出全国 |
| 输出城市列表 CSV | 文件 | 否 | 可选 `.csv` 路径，留空则只在消息窗口显示，不落盘 |

> 筛选为「子串匹配」：填 `上海` 会命中 `上海市`；填 `上海,苏州` 会同时保留上海、苏州两个城市。

## 六、快速上手

1. 运行「获取空气质量数据」，城市名填 `北京市,上海市`（或城市编码 `110000,310000`）；
2. 输出目录选一个文件夹，其余保持默认；
3. 运行后在该目录下得到 5 个数据集（城市级 3 个 + 点位级 2 个）的 `.shp`/`.csv`/`.json`。

> 不确定城市名/编码时，先跑「城市列表查询」确认，再回头抓取。

## 七、输出说明

输出目录下按数据集生成固定命名文件（城市级 3 个 + 点位级 2 个）：

| 数据集 | 内容 | 产物 |
|---|---|---|
| `city_realtime` | 城市实时六参数（每城市 1 行） | `.shp` + `.csv` + `.json` |
| `city_hour` | 城市近 24 小时（24 行/城市） | 同上 |
| `city_day` | 城市近 14 天日报（14 行/城市） | 同上 |
| `station_realtime` | 全部点位实时 | 同上 |
| `station_hour` | 逐点位近 24 小时 | 同上 |

另生成 `progress.json`（各城市 done/failed 状态，断点续跑用）。

> 未勾选对应抓取项时（如「抓取点位级实时」关闭），该数据集不会生成任何文件（`.shp`/`.csv`/`.json` 都不会出现）；只有真正采到数据的集才产出。

- **矢量**：点要素类（WGS-84），属性表含全部字段（含 `lon`/`lat` 经纬度列，与几何一致）。
- **CSV**：UTF-8-BOM，Excel 直开不乱码，缺失值写空串。
- **JSON**：规范化记录数组，缺失值保留 `null`。

### 字段说明

单位：PM2.5、PM10、SO₂、NO₂、O₃ 为 μg/m³，CO 为 mg/m³，AQI 无量纲。

**城市级**：`city_code`、`city_name`、`time_point`（东八区 `YYYY-MM-DD HH:MM:SS`）、`aqi`、`quality`（优/良/轻度污染…）、`primary_pollutant`、`measure`、`unhealthful`、六项浓度 `pm25/pm10/so2/no2/co/o3`、各污染物分指数等级 `*_level`（0–5）、`lon/lat`（该市所有点位坐标的中心点）。

**城市日报**：`day`、`day_str`、日均/24h 浓度 `pm25_24h/pm10_24h/so2_24h/no2_24h/co_24h/o3_8h_24h`。

**点位级**：`station_code`（主键）、`station_name`、`city_code/city_name`、`time_point/time_point_str`，六项浓度 + `o3_8h`，24h 滑动均值 `*_24h`，分指数等级 `*_level`，`no/no_24h/nox/nox_24h`（仅点位实时接口返回），`lon/lat`。

### Shapefile 字段名映射

SHP 受 DBF 字段名 ≤10 字符限制，仅以下字段改名（CSV/JSON 保持原名）：

| 原名 | SHP 名 |
|---|---|
| `station_code` | `stn_code` |
| `station_name` | `stn_name` |
| `time_point_str` | `time_pts` |
| `primary_pollutant` | `prim_poll` |
| `unhealthful` | `unhealth` |
| `o3_8h_level` | `o3_8h_lv` |
| `pm2_5_level` | `pm25_lv` |

### 缺失值约定

- **SHP**：DBF 不支持数值 NULL，无数据被写成 **0**，与真实零值无法区分；
- **CSV**：缺失值写空字符串；
- **JSON**：缺失值保留 `null`。

精确缺失语义请用 **CSV / JSON**。

### 断点续跑

重复运行且输出目录相同、`progress.json` 已有 `done` 城市时，会**自动跳过**已完成城市，只补失败/新增城市。

## 八、常见问题（FAQ）

1. **请控制请求频率**（默认 1 req/s），遵守平台访问约束，勿绕过访问控制。
2. 数据为公开环境监测数据，公开展示 / 再发布 / 商业使用前请确认网站条款与来源标注要求。
3. 城市级经纬度是监测点位坐标**中心点**（非政府驻地）；点位级为各监测点坐标。
4. 历史数据接口仅能取近 24 小时 / 近 14 天，更早数据无法回补，建议从开始使用时持续归档。
