# IsochroneTools 使用说明

基于真实路网的城市**等时圈 / 可达性分析**工具箱，改造自 [Urbankernel/Isochrone](https://github.com/Urbankernel/Isochrone)。

沿真实路网计算「从出发点驾车/步行/骑行 N 分钟能到达哪里」，输出**等时带面（矢量）+ 时间表面栅格**。与「以出发点画直线距离圆」本质不同——所有时间都是沿真实路网、可含实时路况算出来的。

## 一、简介

- **双引擎**：百度批量算路（按「路线数」计配额）+ 腾讯距离矩阵（按「计算次数」计配额）；
- **多出发点**：一次运行可输入多个出发点，自动「逐像元取最小值」合并为一张等时带 + 一张时间栅格；
- **断点续跑**：配额耗尽 / 中断后，重跑自动跳过已完成点对，零浪费；
- **干跑估算**：不发请求，先估算终点数 / 请求次数 / 配额占用，避免一跑就烧光配额；
- **零新增第三方依赖**：IDW 插值用 scipy，等值带提取用 matplotlib，栅格写用 arcpy，均随 ArcGIS Pro 自带。

## 二、环境要求

- ArcGIS Pro（arcpy 3.x，本项目在 3.5.2 实测通过）；
- **无需额外安装任何第三方库**（scipy / numpy / matplotlib / shapely 均自带）。

## 三、目录结构

```
IsochroneTools/
├── IsochroneTools.pyt        # 工具箱入口（2 个工具）
├── isochrone_core/           # 核心包
│   ├── coords.py             # 米↔度换算（复用 geo_common.coords 坐标转换）
│   ├── grid.py               # 渔网终点生成
│   ├── client.py             # 百度批量算路（同步 requests）
│   ├── tencent.py            # 腾讯距离矩阵（同步 requests）
│   ├── interpolate.py        # IDW 插值 + 等值带提取
│   ├── quota.py              # 配额常量 + 干跑估算
│   ├── cache.py              # 断点续跑（results.csv）
│   ├── study_area.py         # 从要素类读范围/出发点
│   ├── writer.py             # 矢量 + 栅格导出
│   └── pipeline.py           # 主流程编排
└── 使用说明.md
```

> **重要**：`IsochroneTools/` 必须与 `geo_common/` 保持同级（`geo_common` 是共享库，等时圈工具的坐标转换、要素类导出、多 key 轮换、限速都依赖它）。

## 四、在 ArcGIS Pro 中加载

用下面任一方式加载（推荐方式二）：

**方式一 · 添加文件夹连接**：在 ArcGIS Pro「目录」窗格中「添加文件夹连接」，定位到 `IsochroneTools` 目录，双击 `IsochroneTools.pyt` 打开。

**方式二 · 添加工具箱（推荐）**：打开 ArcGIS Pro →「目录」窗格 →「工具箱」→ 右键「添加工具箱」，选择 `IsochroneTools/IsochroneTools.pyt`。

工具箱展开后可见「生成等时圈」「干跑估算」两个工具，双击运行。

> 两个工具都**强制前台执行**，避免后台进程把输出路径替换成临时目录导致结果没落到指定位置。

## 五、参数说明

### 5.1 生成等时圈（核心工具）

| #  | 参数        | 类型    | 必填  | 说明                                                     |
| -- | --------- | ----- | --- | ------------------------------------------------------ |
| 1  | 出发点要素类（点） | 要素图层  | ✅   | 一个或多个出发点；从地图「内容」窗格拖入或浏览选择                              |
| 2  | 研究区面要素类   | 要素图层  | ✅   | 等时圈的计算范围（面）                                            |
| 3  | 算路引擎      | 字符串   | ✅   | `baidu`（批量算路）/ `tencent`（距离矩阵）                         |
| 4  | 出行方式      | 字符串   | ✅   | `driving` 驾车 / `walking` 步行 / `riding` 骑行（腾讯下骑行映射为自行车） |
| 5  | 驾车策略      | 字符串   | -   | 仅百度驾车生效：`11` 常规 / `10` 不走高速 / `12` 短距含路况 / `13` 短距无路况  |
| 6  | 等时带阈值     | 字符串   | ✅   | 逗号分隔的分钟数，如 `5,10,15,30`                                |
| 7  | 渔网间距（米）   | 长整型   | ✅   | 默认 300，越小终点越密、请求越多                                     |
| 8  | 栅格分辨率（米）  | 长整型   | ✅   | 时间表面栅格分辨率，默认 50                                        |
| 9  | 百度 AK     | 字符串   | 按引擎 | 多 key 用分号分隔（如 `ak1;ak2`），引擎选 baidu 时必填                 |
| 10 | 腾讯 key    | 字符串   | 按引擎 | 多 key 用分号分隔，引擎选 tencent 时必填                            |
| 11 | QPS       | 双精度型  | ✅   | 每秒请求数，个人开发者建议 3–5                                      |
| 12 | 输出等时带面    | 要素类   | ✅   | 核心成果（.shp / .gpkg），含 `lo/hi/label` 字段                  |
| 13 | 输出时间表面栅格  | 栅格数据集 | ✅   | .tif，float32，单位为分钟                                     |
| 14 | 输出渔网终点    | 要素类   | -   | 可选，宽表 `time_o0/time_o1...` 分钟列                         |
| 15 | 输出不可达点    | 要素类   | -   | 可选，排查路网孤岛                                              |
| 16 | 工作目录      | 文件夹   | -   | 填了才启用断点续跑（`results.csv` 落盘于此）                          |

### 5.2 干跑估算（零配额消耗）

| # | 参数        | 类型   | 说明                  |
| - | --------- | ---- | ------------------- |
| 1 | 出发点要素类（点） | 要素图层 | 同工具 1               |
| 2 | 研究区面要素类   | 要素图层 | 同工具 1               |
| 3 | 算路引擎      | 字符串  | `baidu` / `tencent` |
| 4 | 渔网间距（米）   | 长整型  | 默认 300              |
| 5 | QPS       | 双精度型 | 默认 3.0              |

运行后在「消息」里输出：终点数、请求次数、路线数（配额口径）、预计耗时、并发峰值与调参建议。

## 六、快速上手

### 示例 1：先干跑估算，再正式跑

1. 在内容窗格准备好「出发点」点图层和「研究区」面图层；
2. 先跑「干跑估算」，确认路线数不超过日配额、并发不超限；
3. 若超配额，调大渔网间距再估；
4. 确认无误后跑「生成等时圈」。

### 示例 2：百度驾车等时圈

1. 出发点要素类 → 选出发点；
2. 研究区面要素类 → 选研究区；
3. 算路引擎 → `baidu`，出行方式 → `driving`，驾车策略 → `11`；
4. 等时带阈值 → `5,10,15,30`，渔网间距 → `300`；
5. 百度 AK → 填入你的 AK；
6. 输出等时带面 → `F:\data\isochrone.gpkg`，输出栅格 → `F:\data\idw.tif`；
7. 工作目录 → `F:\data\work`（启用断点续跑）；
8. 运行。


## 七、输出说明

### 等时带面（核心成果）

| 字段        | 类型     | 说明                      |
| --------- | ------ | ----------------------- |
| origin_id | LONG   | 出发点序号（合并后固定为 0）         |
| lo        | DOUBLE | 下界（分钟）                  |
| hi        | DOUBLE | 上界（分钟），开放带为 NULL        |
| label     | TEXT   | 标签，如 `5-10min`、`>30min` |

- 环形带是**带洞**的正确几何（长时段带不会盖住短时段带）；
- 超过最大阈值的区域默认保留为「>最大阈值」开放带（label 如 `>30min`）。

### 时间表面栅格

- GeoTIFF，float32，值为通行分钟数，研究区外 nodata=-9999；
- 在 Pro 里叠加到等时带面下，即可看到连续的时间热力表面。

### 渔网终点（可选）

- 字段 `pid / lon / lat / time_o0 / time_o1 ...`；
- `time_o{id}` 为该点到出发点 id 的通行分钟数，`NULL` 表示不可达。

### 断点续跑

- 工作目录下生成 `results.csv`（`origin_id, oid, duration_min, distance_km`）；
- 重跑同一工作目录时，自动跳过已有有效时长的点对；
- 配额耗尽 / 中断后，直接重跑即可续跑，不重复计费。

## 八、常见问题（FAQ）

**Q1：为什么跑得慢 / 报「并发超限（401）」？**  
百度按「路线数」计并发（上限约 50 条/秒），QPS 设太高会触发 401。先跑「干跑估算」看并发峰值，按建议调低 QPS。

**Q2：报「所有 N 个 AK 均不可用」？**  
多个 AK 都已配额耗尽或失效。明天配额重置后再跑（工作目录里 `results.csv` 还在，可续跑），或补充新 AK。

**Q3：腾讯引擎报 `status=1023`？**  
腾讯配额/并发超限。腾讯个人开发者默认 6000 次/天、并发 5 次/秒，检查 QPS 与渔网间距。

**Q4：等时带面只生成了一两条？**  
检查渔网终点是否够密（可缩小渔网间距）、研究区是否太小、阈值是否合理。有效采样点 < 3 时无法插值。

**Q5：结果没落到指定路径？**  
两个工具都强制前台执行。若仍异常，检查输出目录是否有写入权限。

**Q6：坐标是什么坐标系？**  
成果一律 WGS-84。请求链路按引擎自动转换，用户无需关心。

**Q7：结果里有「>30min」的开放带，能去掉吗？**  
默认保留开放带（label `>30min`）。如需去掉，可在 `pipeline.py` 的 `extract_contours` 调用处把 `keep_over=True` 改为 `False`。
