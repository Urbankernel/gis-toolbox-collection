# 名称转 AOI 面工具箱（GetAOITools）使用说明

## 一、简介

本工具箱在 ArcGIS / ArcGIS Pro 中，把一份**地名清单**（如小区、学校、商圈、景区名称）自动转换为对应的 **AOI 兴趣面边界**（多边形要素类），输出 SHP / GeoPackage。

核心能力：

- **端到端自动化**：名称 → 检索 → 候选过滤 → 综合排序 → 抠取边界 → 坐标转换 → 输出 AOI 面；
- **双数据源**：支持高德（GCJ-02）与百度（bd09mc），两种坐标自动统一转成 WGS-84；
- **灵活候选处理**：多结果取舍策略、分类白名单、面积范围过滤；
- **统一 WGS-84** 输出，可选投影到其他坐标系。

## 二、环境要求

| 依赖 | 说明 |
| --- | --- |
| ArcGIS Pro（arcgispro-py3 环境） | 自带 `arcpy`、`requests` |
| `shapely` | 需额外安装，用于 AOI 边界几何构建与写面 |

安装 `shapely`（需在 **ArcGIS Pro 的 Python 环境**中执行，请用管理员权限打开命令行）：

```powershell
# 进入 ArcGIS Pro 自带 Python 环境
cd "C:\Program Files\ArcGIS\Pro\bin\Python\envs\arcgispro-py3"
python -m pip install shapely
```

> 注意：不要装到用户目录（`--user`）——ArcGIS Pro 后台进程不加载用户 site-packages，会导致运行时仍报 `ModuleNotFoundError: shapely`。

## 三、目录结构

工具箱采用「薄 `.pyt` + 核心包 + 共享库」结构，请保持如下相对位置，不要移动单独文件：

```
github_arcgis_tools/
├── geo_common/                 # 共享公共库（坐标转换 / 导出等）
├── AMapPOITools/               # 另一个工具箱，与本工具箱相互独立
└── GetAOITools/
    ├── GetAOITools.pyt         # 在 ArcGIS Pro 中加载这个文件
    └── get_aoi_core/           # 名称转 AOI 核心包
```

## 四、在 ArcGIS Pro 中加载

用下面任一方式加载（推荐方式二）：

**方式一 · 添加文件夹连接**：在 ArcGIS Pro「目录」窗格中「添加文件夹连接」，定位到 `GetAOITools` 目录，双击 `GetAOITools.pyt` 打开。

**方式二 · 添加工具箱（推荐）**：打开 ArcGIS Pro →「目录」窗格 →「工具箱」→ 右键「添加工具箱」，选择 `GetAOITools/GetAOITools.pyt`。

加载后展开工具箱，双击 **「名称转 AOI 面」** 打开参数面板，填好参数点击 **运行**，进度实时显示在「地理处理 → 消息」中。

## 五、参数说明

### 5.1 输入（二选一，至少填一个）

| # | 参数名 | 显示名 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | names_csv | 地名清单 CSV | 二选一 | 每行一个地名（推荐，支持带列头） |
| 2 | names_text | 地名清单（TXT 文件） | 二选一 | 选择 .txt 文件，每行一个地名；城市由「全局城市」兜底（兼容 UTF-8/GBK 编码） |

### 5.2 数据源

| # | 参数名 | 显示名 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 3 | provider | 数据源 | 是 | amap | `amap`（高德）或 `baidu`（百度） |
| 4 | api_keys | 高德 Key / 百度 AK（可多选） | 是 | — | 按所选数据源填对应 Key；填多个时本次使用第一个 |
| 5 | city | 全局城市 | 否 | — | 如 `杭州市`，缩小检索范围、提高匹配精度 |

> - 高德 Key 申请：[高德开放平台](https://lbs.amap.com/)（选择「Web 服务」类型）
> - 百度 AK 申请：[百度地图开放平台](https://lbsyun.baidu.com/)（选择「服务端」类型）

### 5.3 候选处理

| # | 参数名 | 显示名 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 6 | want | 多结果取舍 | 是 | all | `all` 保留全部匹配 / `main` 只取主结果 / `keyword` 只取含关键词的分支 |
| 7 | keyword | 分支关键词 | 否 | — | 仅当 `want=keyword` 时启用，按关键词筛选分支 |
| 8 | keep_types | 分类白名单（逗号分隔） | 否 | — | 只保留指定 POI 类型的候选，如 `小区,学校` |
| 9 | min_area | 最小面积（km²） | 否 | 0.0 | 过滤过小的 AOI |
| 10 | max_area | 最大面积（km²） | 否 | 1000000.0 | 过滤过大的 AOI |
| 11 | max_candidates | 每地名最大候选数 | 否 | 25 | 单地名保留的最大候选数量 |

### 5.4 请求

| # | 参数名 | 显示名 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| 12 | min_interval | 请求最小间隔（秒） | 3.0 | 随机延迟下限，降低被反爬风险 |
| 13 | max_interval | 请求最大间隔（秒） | 10.0 | 随机延迟上限 |
| 14 | retries | 单请求最大重试 | 3 | 失败自动重试 |
| 15 | timeout | 请求超时（秒） | 15.0 | 单次请求超时时间 |

### 5.5 输出

| # | 参数名 | 显示名 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 16 | output_features | 输出 AOI 面要素类 | 是 | — | 仅支持 `.shp` 或 `.gpkg`，可浏览选择或手动输入路径 |
| 17 | output_crs | 输出坐标系 | 否 | GCS_WGS_1984 | 目标投影；留空/填 WGS-84 则不投影 |

### 5.6 高级（可选）

| # | 参数名 | 显示名 | 说明 |
| --- | --- | --- | --- |
| 18 | boundary_cookie | 边界接口 Cookie | 高德边界接口触发反爬时，可粘贴浏览器 Cookie 兜底 |
| 19 | boundary_ua | 边界接口 User-Agent | 同上，自定义 User-Agent |

## 六、输出说明

运行成功后会生成 **一个 AOI 面要素类**（GPKG 内图层名为 `aoi`），每个地名可能对应 0 个或多个面。若某个地名完全未匹配到，会在消息中按「无候选 / 无边界」归类统计，不会中断整体流程。

### 6.1 AOI 面属性字段（20 个）

`poi_id`、`name`（匹配到的标准名）、`input_name`（输入的地名）、`provider`（数据源）、`poi_type`、`address`、`area_km2`（面积）、`status`（匹配状态：Matched 等）、`typecode`、`type`、`newtype`、`adcode`、`citycode`、`cityname`、`districtname`、`tel`、`tag_show_info`、`t_tag_list`、`t_tag`、`tag_display`。

> 编码类字段（`typecode` / `adcode` / `citycode` 等）统一存为文本，避免前导 0 丢失；标签数组字段存为 JSON 字符串。

### 6.2 SHP 与 GPKG 的区别

| 项目 | SHP | GPKG |
| --- | --- | --- |
| 字段名 | 超过 10 字符自动映射/截断 | 保留原字段名 |
| 文本长度 | 最长 254 字符 | 更长 |
| 数据结构 | 多文件 | 单文件数据库 |

SHP 超长字段名映射关系：`districtname→district`、`tag_show_info→tag_show`、`tag_display→tag_disp`。

## 七、常见问题（FAQ）

**Q1：运行时报 `ModuleNotFoundError: shapely`？**
shapely 未装到 ArcGIS Pro 的 Python 环境，请按「二、环境要求」在管理员命令行下安装。

**Q2：运行报 `ModuleNotFoundError: geo_common`？**
目录结构被破坏或移动了文件，请恢复「三、目录结构」的相对位置（`GetAOITools` 与 `geo_common` 必须同级）。

**Q3：结果没有落到我指定的路径？**
本工具强制前台执行以保证路径可靠。请确认「地理处理 → 选项」未强制后台；若仍异常，检查输出路径是否有写权限。

**Q4：某个地名没匹配到 AOI？**
- 确认数据源 Key 正确、权限类型匹配（高德选「Web 服务」、百度选「服务端」）；
- 补充「全局城市」以缩小范围；
- 尝试切换数据源（高德 ↔ 百度）交叉验证；
- 检查 `keep_types` 白名单或面积范围是否误过滤。

**Q5：高德源被反爬、边界抠取失败？**
在「高级」参数中填入边界接口的 `Cookie` 与 `User-Agent`（从浏览器开发者工具复制）后重试。

**Q6：AOI 边界看起来有偏移？**
输出已统一为 WGS-84。若在带偏移的底图上叠加，请确认底图坐标系一致；原始 GCJ-02/bd09mc 转换由工具内部自动完成，无需手动处理。
